# Генератор QR-кода для контактов (vCard)

Это веб-приложение на Flask позволяет быстро и легко создавать QR-коды, содержащие вашу контактную информацию в формате vCard. При наведении камеры смартфона на этот QR-код, контакт можно сразу же сохранить в адресную книгу данного смартфона.

## Возможности

-   **Генерация vCard:** Создает файл контакта с именем, должностью, телефонами, email, адресом и сайтом.
-   **Настройка полей:** Форма позволяет ввести как обязательные (ФИО, должность, email, рабочий телефон), так и при необходимости дополнительные данные (добавочный номер, мобильный телефон).
-   **Визуальный QR-код:** Генерирует чистый черно-белый QR-код с тихой зоной вокруг.
-   **Предпросмотр:** Сразу после генерации показывает полученный QR-код на странице.
-   **Скачивание и печать:** Готовое изображение можно скачать в формате PNG или отправить на печать прямо из браузера.
-   **Логирование:** Все созданные vCard записываются в лог (stdout) для отслеживания модератором web-страницы — в контейнере логи смотрятся через `docker compose logs`.
-   **Запуск в Docker:** Production-развертывание одной командой `docker compose up -d` (gunicorn + nginx reverse proxy).

## Технологии

-   **Backend:** Python (Flask)
-   **Production-сервер:** `gunicorn` (WSGI) в Docker-контейнере
-   **Генерация QR:** `qrcode` (библиотека Python)
-   **Создание vCard:** `vobject`
-   **Работа с изображениями:** `Pillow` (PIL)
-   **Frontend:** HTML, CSS, JavaScript

## Настройка

Все настройки «под компанию» вынесены в файл `.env` — код править не нужно.

1. Создайте `.env` из примера:

```bash
cp .env.example .env
```

2. Откройте `.env` и укажите данные вашей компании:

- `COMPANY_NAME` — название организации (подставляется в должность контакта).
- `COMPANY_SITE` — адрес сайта.
- `COMPANY_ADDRESS_STREET` / `CITY` / `REGION` / `CODE` / `COUNTRY` — физический адрес.
- `FORM_EMAIL_DEFAULT` — предзаполненное значение поля email (например, домен корпоративной почты).
- `FORM_WORK_PHONE_DEFAULT` — предзаполненное значение поля рабочего телефона.
- `FLASK_DEBUG` — режим отладки (`true`/`false`, по умолчанию `true`).
- `FLASK_HOST` — адрес запуска (по умолчанию `127.0.0.1`).
- `FLASK_PORT` — порт (по умолчанию `5000`).
- `GUNICORN_WORKERS` — количество worker-процессов gunicorn (по умолчанию `2`, используется только при запуске в Docker).

Переменные `FLASK_DEBUG`/`FLASK_HOST`/`FLASK_PORT` относятся только к локальному запуску (`python app.py`); в Docker-контейнере приложение запускает gunicorn на порту 8000 и эти переменные не используются.
- `CARD_TEMPLATE_URL` — адрес для кнопки «Шаблоны визиток» (http-ссылка или сетевой путь). Кнопка показывается, только если переменная задана; по умолчанию скрыта.

Если `.env` отсутствует или переменная не задана — используются демо-значения по умолчанию. Файл `.env` не коммитится (добавлен в `.gitignore`), в репозитории лежит только пример `.env.example`.


3. Формат номера телефона

- Номера телефонов сохраняются в vCard в том виде, в котором они введены в форме. Маска ввода `+7(XXX)XXX-XX-XX` применяется на клиенте (JavaScript), но на сервере номер не форматируется.

## Использование

- Заполните все поля формы. Обязательные поля отмечены звездочкой (*).
- Нажмите кнопку "Сгенерировать QR-код".
- Справа появится готовое изображение с QR-кодом.
- Нажмите "Скачать", чтобы сохранить его на компьютер, или "Печать", чтобы распечатать.

## Проверка совместимости со старыми телефонами

vCard формируется в формате 3.0 со значением в UTF-8; каждое текстовое поле
(`FN`, `TITLE`, `ADR`, `EMAIL`, `URL`, `TEL`) помечено параметром `CHARSET=UTF-8`,
чтобы кириллица корректно читалась на устройствах, которые без явного объявления
кодировки трактуют байты как ANSI.

Автоматически это проверяется только на уровне текста: тесты `tests/test_app.py`
контролируют наличие `CHARSET` на каждом поле, совпадение UTF-8-байтов vCard с
байтами QR-кода и предел длины строки (75 октетов). Проверить, как контакт
откроется на телефоне, можно только вручную — декодера QR в окружении проекта нет.

### Что проверять

1. Запустить приложение (`python app.py`, см. «Установка и запуск»).
2. Заполнить форму данными **с кириллицей во всех полях**: ФИО кириллицей,
   должность кириллицей, рабочий телефон, добавочный (например, `доб. 12`),
   мобильный, e-mail с кириллическим доменом (например, `ivanov@рога.рф`).
   В `.env` задать `COMPANY_SITE` и `COMPANY_ADDRESS_STREET` кириллицей, а
   `COMPANY_NAME` — достаточно длинным, чтобы строка `TITLE` переносилась
   (проверяется многострочный перенос).
3. Нажать «Сгенерировать QR-код» и отсканировать результат камерой телефона.
4. Сравнить контакт, предложенный к сохранению, с введёнными данными.

### Что считается провалом

| Симптом | Что это значит |
|---|---|
| В ФИО или должности вместо кириллицы — «??????» или пустые символы | Клиент не учёл `CHARSET=UTF-8` |
| Поле e-mail или телефон предлагает импортировать как `vCard`, но текст внутри нечитаем | Клиент строже к `CHARSET` на `EMAIL` / `TEL`, чем к `FN` / `TITLE` |
| Контакт не предлагается сохранить вообще, сканер показывает просто текст | QR не распознан как vCard — это уже не про кодировку, проверьте, не превышен ли объём данных |
| Сайт или адрес показываются пустыми | Клиент не принял `CHARSET` на `URL` / `ADR` |

### Матрица проверки

Отмечать нужно конкретные устройства и версии ОС — иначе через полгода
невозможно отличить выполненную проверку от невыполненной.

| Устройство | Версия ОС | ФИО и должность | Телефоны | e-mail | Сайт и адрес | Дата | Итог |
|---|---|---|---|---|---|---|---|
| iPhone | iOS | ок | ок | ок | ок | 2026-09-30 | пройдено |
| Android-устройство | Android 13 | ок | ок | ок | ок | 2026-09-30 | пройдено |
| _старая версия Android (6–8)_ | _не проверено_ | — | — | — | — | — | **не проверено** |

Минимум — одна старая версия Android (Android 6–8, где актуальны сторонние
сканеры и Google Contacts) и один iPhone.

> **Проверено не полностью.** Современные iOS и Android 13 проходят, но самый
> рискованный случай — старые Android, где сканер может строже отнестись к
> `CHARSET=UTF-8` на `EMAIL` / `URL` / `TEL`, — не проверен. Строка матрицы
> выше остаётся незаполненной намеренно: если устройства с Android 6–8 под рукой
> не будет, это ограничение нужно учитывать при следующем обновлении `vobject`
> или `qrcode` — обе библиотеки участвуют в сериализации vCard и кодировании QR.

## Запуск в Docker (production)

Для размещения на сервере приложение упаковано в Docker-образ: gunicorn (production WSGI-сервер) слушает порт 8000 внутри контейнера.

> **Для администратора сервера:** готовая пошаговая инструкция по развертыванию — в файле [DEPLOY.md](DEPLOY.md) (там же — что менять при развертывании других приложений по этой схеме).

Рекомендуемая схема на сервере с несколькими проектами — **единый nginx в контейнере** перед всеми приложениями. Приложения не публикуют порты на хост: nginx обращается к ним по имени контейнера через общую Docker-сеть. Наружу смотрят только порты nginx (80/443).

### 1. Создайте общую сеть (один раз на сервере)

```bash
docker network create nginx-net
```

Эту же сеть (`external: true`) указывают в своих `docker-compose.yml` все проекты и контейнер с nginx.

### 2. Подготовьте настройки

```bash
cp .env.example .env
# отредактируйте .env — укажите данные вашей компании
```

### 3. Соберите образ и запустите контейнер

```bash
docker compose up -d --build
```

Контейнер называется `qr-app` (зафиксировано в `docker-compose.yml`) — по этому имени к нему обращается nginx. Порт на хосте не публикуется: приложение доступно только внутри сети `nginx-net`.

### 4. Управление контейнером

```bash
docker compose logs -f        # логи в реальном времени
docker compose restart        # перезапуск
docker compose down           # остановка и удаление контейнера
docker compose up -d --build  # обновление (пересборка после изменения кода)
```

Конфигурация запуска зафиксирована в `docker-compose.yml`:

- **Сеть:** общая `nginx-net` (external), имя контейнера `qr-app`.
- **Настройки:** передаются через `env_file: .env` (файл не вшивается в образ).
- **Автоперезапуск:** `restart: unless-stopped` — контейнер поднимается после перезагрузки сервера.
- **Workers:** количество процессов gunicorn задаётся переменной `GUNICORN_WORKERS` в `.env` (по умолчанию 2).

### 5. Настройка nginx (reverse proxy)

Предполагается, что nginx тоже работает в контейнере и подключён к той же сети `nginx-net`, а конфиги проектов лежат в `conf.d/` (смонтированном в контейнер nginx). Пример `conf.d/qr.conf`:

```nginx
server {
    listen 443 ssl;
    server_name qr.example.com;

    # ssl_certificate / ssl_certificate_key — ваши сертификаты

    location / {
        proxy_pass http://qr-app:8000;   # имя контейнера из docker-compose.yml
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Для каждого следующего проекта заводите свой файл в `conf.d/` с другим `server_name` и именем его контейнера в `proxy_pass` (например, `http://app2:8000`).

Важные нюансы:

- **Порядок запуска:** сначала сеть и приложения, затем nginx. Nginx резолвит имя из `proxy_pass` при старте — если контейнер приложения не запущен, nginx завершится с ошибкой `host not found in upstream`.
- **После изменения conf.d** перечитайте конфиг: `docker exec <имя-контейнера-nginx> nginx -s reload`.
- **При пересоздании контейнера приложения** (`up -d --build`) имя и сеть сохраняются, nginx перезапускать не нужно.

## Логирование

Приложение пишет логи (включая полный текст каждой созданной vCard) в **stdout** — это стандарт для Docker: логи собирает и хранит Docker, а не файлы внутри контейнера. Файл `logs/info.log` больше не ведётся.

### Как посмотреть логи

```bash
docker compose logs             # все накопленные логи контейнера
docker compose logs -f          # следить в реальном времени
docker compose logs --tail 100  # последние 100 строк
docker compose logs --since 1h  # за последний час
```

Имя контейнера знать не нужно — команды выполняются из каталога проекта. При локальном запуске (`python app.py`) логи выводятся в консоль.

### Где хранятся логи и ротация

Логи хранит logging driver Docker (`json-file`) в `/var/lib/docker/containers/<id-контейнера>/`. Ротация настроена в `docker-compose.yml`: файлы по 10 МБ, хранится 3 архивные копии — старые логи удаляются автоматически.

### Выгрузка логов (аудит)

```bash
docker compose logs > audit.txt
```
