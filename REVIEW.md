## Замечания

### 1. `readme.md` противоречит коду (логи)

**readme.md:217** пишет:
> Приложение пишет логи (включая полный текст каждой созданной vCard) в stdout

Но `app.py:91` логирует только имя:
```python
logging.info(f"Создана vCard для: {name}")
```

**Либо** readme устарел, **либо** код изменился и документацию не обновили. Нужно привести в соответствие.

### 2. `readme.md` противоречит коду (закомментированный код)

**readme.md:130** пишет:
> В функции `generate_vcard()` закомментированы альтернативные способы обработки рабочего и добавочного номеров.

В текущем `app.py` таких закомментированных блоков нет. По git-истории видно, что раньше был закомментированный блок с `note` для добавочного номера — его удалили в v2.1.0 (change `housekeeping-fixes`). readme не обновили.

### 3. `readme.md` противоречит коду (структура проекта)

**readme.md:86-98** в структуре не упоминает:
- `tests/` — 26 тестов
- `openspec/` — спецификации
- `VERSION`, `CHANGELOG.md`, `backlog.md`, `DEPLOY.md`, `AGENTS.md`
- `.env.example`

### 4. `readme.md` противоречит коду (enctype формы)

**index.html:30** форма использует `enctype="multipart/form-data"`, хотя файлы не загружаются — только текстовые поля. Это избыточно и слегка замедляет отправку. Можно убрать.

### 5. `MAX_FIELD_LENGTH` и `MAX_NAME_LENGTH` не используются

**app.py:29-30** объявляет константы:
```python
MAX_FIELD_LENGTH = 500
MAX_NAME_LENGTH = 200
MAX_EMAIL_LENGTH = 254
```

Ни одна не используется в валидации. Либо добавить проверки длины, либо удалить константы.

### 6. Устаревший контекст в `openspec/config.yaml`

**openspec/config.yaml:15-17** пишет:
> весь backend в app.py (один модуль: 3 функции + 2 роута), templates/index.html, static/ (style.css, main.js, white_page_square.png), logs/info.log — логи создаваемых vCard (в .gitignore).

Реальность:
- Функций уже больше (`generate_vcard`, `generate_qr_code`, `generate_qr_image`, `create_business_card`, `validate_form`, `inject_form_defaults`)
- `white_page_square.png` удалён в v2.0.0
- `logs/info.log` больше не ведётся (v2.3.0)
- Тесты есть (26 штук)

### 7. Мёртвый CSS

**style.css:143-158** — стили `.file-input` не используются (ни одного `<input type="file">` в шаблоне).
**style.css:160-165** — стили `.help-text` не используются.
**style.css:330-336** — стили `input[type="checkbox"]` не используются.

### 8. Мёртвый HTML

**index.html:15** — закомментированный `<!-- <div style="display: none;">IIS_PROXY_TEST</div> -->` — мусор.

### 9. Мёртвый JS

**main.js:1-11** — функция `showCopyTooltip()` объявлена на верхнем уровне, но вызывается только внутри `DOMContentLoaded`. Это нормально, но сама функция не инкапсулирована — попадает в глобальную область. Мелочь.

### 10. Нет тестов на маску телефона

`formatPhone()` в `main.js` — нетривиальная логика (нормализация 8/7, скобки, дефисы), но тестов нет. JS-тесты можно было бы добавить через Node.js + простой assert.

### 11. Нет теста на длину полей

Константы `MAX_FIELD_LENGTH` и др. объявлены, но не используются. Если добавить валидацию длины — нужен тест.

### 12. `generate_qr_image` — мёртвая функция

**app.py:105-110** — функция `generate_qr_image()` не вызывается нигде (в роуте используется `create_business_card`). Либо удалить, либо использовать.

### 13. Нет обработки ошибок при генерации QR

Если `qrcode` или `vobject` упадут (например, из-за некорректных данных), пользователь увидит 500 без объяснений. Можно добавить try/except с человекочитаемым сообщением.

### 14. Нет rate limiting

Форма открыта для злоупотреблений — можно спамить запросами. Для внутреннего инструмента это критично вряд ли, но для публичного — стоит подумать.

### 15. Потенциальная проблема с кодировкой кириллицы в vCard

`vobject` по умолчанию сериализует в UTF-8, но некоторые старые телефоны могут некорректно прочитать vCard без явного `CHARSET=UTF-8`. Стоит проверить на реальном устройстве.
