# Design: externalize-company-config

## Context

`app.py` — единственный модуль приложения. Настройки компании захардкожены в `generate_vcard()` (название, сайт, адрес), позиция и размер QR — константы `QR_X_POS`/`QR_Y_POS` и литерал `0.9` в `create_business_card()`. Пользователь выбрал формат `.env` (переменные окружения) вместо YAML. См. proposal.md — Why.

## Goals / Non-Goals

**Goals:**

- Все настройки «под компанию» правятся в `.env`, код не трогается.
- Свежий клон работает без `.env` (встроенные демо-дефолты).
- Реальные данные компании не коммитятся (`.env` в `.gitignore`).

**Non-Goals:**

- Вложенная структура конфига (`.env` плоский по своей природе — принято).
- Валидация значений, горячая перезагрузка без рестарта.
- Другие настройки (ссылка «Шаблоны визиток», `debug`/`host`) — отдельные changes.

## Decisions

1. **`.env` + `python-dotenv`, а не YAML.**
   Решение пользователя. `load_dotenv()` при старте подгружает `.env` в `os.environ`; код читает `os.getenv("ИМЯ", "дефолт")`. Плоскость формата компенсируется понятными именами (`COMPANY_ADDRESS_STREET` и т.д.).
   _Альтернатива:_ `config.yaml` — отвергнута пользователем.

2. **Дефолты прямо в `os.getenv()` — текущие демо-значения.**
   Приложение без `.env` ведёт себя ровно как сейчас. Не нужен отдельный модуль конфигурации: чтение переменных — одна строка в месте использования.
   _Альтернатива:_ падать при отсутствии `.env` — отвергнута, ломает «из коробки».

3. **Имена переменных:**
   `COMPANY_NAME`, `COMPANY_SITE`, `COMPANY_ADDRESS_STREET`, `COMPANY_ADDRESS_CITY`, `COMPANY_ADDRESS_REGION`, `COMPANY_ADDRESS_CODE`, `COMPANY_ADDRESS_COUNTRY`, `QR_X_POS`, `QR_Y_POS`, `QR_SIZE_RATIO`, `FORM_EMAIL_DEFAULT`, `FORM_WORK_PHONE_DEFAULT`.
   Числовые (`QR_X_POS`, `QR_Y_POS`, `QR_SIZE_RATIO`) приводятся через `float()`.

3.1 **Значения полей формы передаются в шаблон через `app.context_processor`.**
   Оба роута (`GET /` и `POST /generate`) рендерят `index.html`; context processor гарантирует, что `email_default` и `phone_default` доступны в обоих без дублирования кода.
   _Альтернатива:_ передавать переменные в каждом `render_template` — отвергнута, дублирование.

4. **Константы `QR_X_POS`/`QR_Y_POS` на уровне модуля заменяются чтением из окружения** — сохраняют имена и семантику, чтобы diff был минимальным.

## Risks / Trade-offs

- [Пользователь забудет создать `.env` и удивится демо-данным] → `.env.example` с комментариями + раздел «Настройка» в readme; дефолты безопасны (демо-данные).
- [`float()` упадёт на мусоре в переменной] → Принято: валидация конфига вне объёма; ошибка будет явной при старте.
- [Числа с запятой (`0,055`) не распарсятся] → В `.env.example` значения с точкой и комментарий о формате.

## Migration Plan

1. `pip install -r requirements.txt` (подтянется `python-dotenv`).
2. `cp .env.example .env` и отредактировать под свою компанию (опционально — без `.env` работают дефолты).
3. Откат: удалить `.env`, вернуться на предыдущий коммит.
