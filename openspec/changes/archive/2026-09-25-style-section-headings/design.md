# Design: style-section-headings

## Context

Сейчас `h1` имеет только `text-align: center`, а надписи разделов — `<p class="fill-form">` без стилизации. Палитра уже задана переменными в `:root` (`--primary-color: #009639`, акцент `#ffc107` у кнопки шаблонов и блока `.attention`). Требования — см. delta-спеку `specs/web-interface/spec.md`.

## Goals / Non-Goals

**Goals:**

- Заголовок страницы и заголовки разделов получают акцентное оформление в существующей палитре.
- Только системные шрифты, ноль внешних запросов.
- Не сломать выравнивание колонок, мобильный и печатный макеты.

**Non-Goals:**

- Редизайн остальных элементов (кнопки, поля, фоны секций).
- Внешние/локальные font-файлы (решение пользователя).

## Decisions

### Решение 1: шрифт заголовков — основной sans-serif (пересмотрено)

Изначально выбран системный serif-стек (Georgia и т.п.) — **отклонён пользователем на визуальной проверке**. Заголовки используют тот же системный sans-serif, что и остальной текст; акцент создаётся цветом, весом (600) и подложкой, а не шрифтовой парой.

**Альтернативы:** serif-стек (отклонён пользователем), декоративный Google Font (отклонён — сеть), локальный woff2 (отклонён — бинарные файлы, лицензии).

### Решение 2: полупрозрачные подложки в существующей палитре

Принятая практика — «tint» акцентного цвета с непрозрачностью 8–20%:

- `h1`: фон `rgba(0, 150, 57, 0.08)` (от `--primary-color`), текст тёмно-зелёный `#007e30` (уже есть как `--hover-color`) — контраст к подложке достаточный; тонкая рамка `1px solid rgba(0, 150, 57, 0.2)`. Компактные отступы `padding: 10px 20px` и `border-radius: 12px` — полноразмерная плашка давала лишнюю высоту (появилась прокрутка страницы).
- Заголовки разделов: фон `rgba(255, 193, 7, 0.18)` (от `#ffc107`), текст тёмно-янтарный (производная от `#e4ab00`, например `#8a6d00`) — жёлтый текст на жёлтой подложке нечитаем, поэтому тёмный оттенок.

Значения добавляются переменными в `:root` (по конвенции файла) — тема остаётся настраиваемой в одном месте.

### Решение 3: заголовок раздела — шапка карточки, а не «плашка-кнопка» (пересмотрено)

`<p class="fill-form">` заменяется на `<h2 class="fill-form">` (три места: «Заполните форму», заглушка, «Ваш QR-код, …») — иерархия `h1 → h2`, лучше для скринридеров.

Первоначально подложка была скруглённой плашкой внутри карточки — **пользователь отметил, что выглядит как кнопка**. Теперь подложка — шапка белой карточки: растянута вровень с верхней, левой и правой гранями (отрицательные поля `-30px`, компенсирующие `padding: 30px` карточки), скруглены только верхние углы (`border-radius: 20px 20px 0 0` — как у карточки), нижний отступ отделяет шапку от содержимого. Обе карточки имеют одинаковую структуру — требование «надписи на одном вертикальном уровне» сохраняется автоматически.

### Решение 4: размеры с учётом высоты страницы и мобильного макета (пересмотрено)

Первая версия дала лишнюю высоту — появилась вертикальная прокрутка. Компактные размеры: `h1` — 28px (на мобильном 24px, ранее правило было 36px), заголовки разделов — 20px. Печатный макет не трогаем: браузеры по умолчанию не печатают фоны, текст останется читаемым.

## Risks / Trade-offs

- [На Linux без MS-шрифтов Georgia может подмениться] → стек из 4 шрифтов + generic `serif`; внешний вид деградирует gracefully.
- [Жёлтая подложка может выглядеть кричаще] → непрозрачность 0.18 и тёмно-янтарный текст держат её приглушённой; оттенок легко скорректировать переменной.
- [Подложки меняют высоту надписей → риск для выравнивания колонок] → обе надписи используют один класс с одинаковыми отступами, уровень сохраняется; проверяется ручной проверкой и сценарием спеки.
