# Design: preserve-form-values

## Context

Форма отправляется классическим POST на `/generate` с полной перезагрузкой страницы: сервер рендерит `index.html` заново, и значения полей теряются. Мотивация и целевое поведение — см. proposal.md и delta-спеку `specs/web-interface/spec.md`.

## Goals / Non-Goals

**Goals:**

- Передать введённые значения из обработчика POST в шаблон и вывести их в полях формы.
- Сохранить текущее поведение GET `/` (дефолты из `.env`).
- Минимальные правки, без изменения архитектуры и JS.

**Non-Goals:**

- AJAX-отправка формы (fetch) — рассматривалась, отклонена пользователем.
- Хранение между визитами (localStorage/сессии) — отклонено пользователем.

## Decisions

### Решение 1: «липкая форма» на сервере (sticky form), а не AJAX

Обработчик `generate_card` передаёт введённые значения обратно в `render_template`, шаблон подставляет их в атрибуты `value` полей.

**Почему:** минимальные изменения (2 ветки одного роута + атрибуты `value` в шаблоне), классическая практика для server-rendered форм, не трогает `main.js` (маски телефонов, клиентская валидация, копирование в буфер продолжают работать). Решение подтверждено пользователем.

**Альтернатива:** fetch + динамическая подстановка QR — данные в полях остались бы сами собой, но потребовала бы переработки обработки ошибок, потока скачивания/печати и JS; избыточно для этой задачи.

### Решение 2: приоритет значений — «введённое или дефолт»

В шаблоне для каждого поля используется переданное значение, если оно есть, иначе дефолт (для email/рабочего телефона — из `context_processor`, для остальных — пустая строка). Это автоматически даёт правильное поведение и для GET `/` (значения не передаются — показываются дефолты), и для POST (показывается введённое).

### Решение 3: ветка ошибки валидации (HTTP 400) тоже возвращает значения

При ошибке валидации в шаблон передаются те же введённые значения, что и при успехе. Пользователь видит сообщение об ошибке и все свои данные, исправляет только проблемное поле.

## Risks / Trade-offs

- [XSS через отражённые значения полей] → Jinja2 экранирует переменные по умолчанию; использовать обычную интерполяцию `{{ ... }}` без `| safe`.
- [Маска телефона и введённое значение] → маски в `main.js` срабатывают на ввод; подставленное сервером значение уже отформатировано пользователем при вводе, конфликта нет.
- [Регрессия дефолтов на GET] → покрывается существующими тестами и новым тестом на GET.
