# Proposal: preserve-form-values

## Why

После отправки формы (POST `/generate`) страница перерисовывается, и все введённые пользователем данные пропадают: поля ФИО, должность, добавочный и мобильный телефоны становятся пустыми, а email и рабочий телефон сбрасываются на значения по умолчанию из `.env`. То же происходит при ошибке серверной валидации (HTTP 400) — пользователь вынужден вводить всё заново. Это мешает главному сценарию «сгенерировал → заметил опечатку → поправил → сгенерировал снова» и противоречит общепринятой практике «липких форм» (sticky form).

## What Changes

- При успешной генерации (HTTP 200) форма отображается с только что введёнными значениями во всех полях — пользователь может исправить любое поле и сгенерировать QR-код повторно.
- При ошибке валидации (HTTP 400) форма также отображается с введёнными значениями, чтобы пользователь исправлял только проблемное поле.
- При первом открытии страницы (GET `/`) поведение не меняется: email и рабочий телефон предзаполнены значениями по умолчанию из `.env` (или демо-значениями), остальные поля пусты.
- Введённые значения имеют приоритет над значениями по умолчанию: если пользователь изменил email или рабочий телефон, после отправки показывается его значение, а не дефолт.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `web-interface`: меняется требование «Форма ввода контактных данных» — после отправки формы (и успешной, и с ошибкой валидации) поля ДОЛЖНЫ показывать введённые пользователем значения, а не значения по умолчанию/пустые.

## Impact

- `app.py`: обработчики `generate_card` (обе ветки — успех и ошибка валидации) передают введённые значения формы в шаблон.
- `templates/index.html`: поля формы выводят переданные значения (с откатом на дефолты для email/рабочего телефона при первом открытии).
- `tests/`: новые тесты на сохранение значений после POST (успех и ошибка валидации).
- Спецификация `openspec/specs/web-interface/spec.md`: обновление требования и сценариев.
- Зависимости и API не меняются; обратная совместимость сохраняется.

## Не входит в объём

- Сохранение данных между визитами/перезагрузками страницы (localStorage, сессии, куки) — по решению пользователя не делаем.
- Перевод формы на AJAX (fetch) без перезагрузки страницы.
- Кнопка «Очистить форму».
- Изменение логики генерации vCard/QR-кода и серверной валидации.
