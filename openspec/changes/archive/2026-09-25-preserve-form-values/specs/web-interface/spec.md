# web-interface Specification (delta)

## MODIFIED Requirements

### Requirement: Форма ввода контактных данных

Система ДОЛЖНА (SHALL) отображать на главной странице (GET `/`) форму с полями: ФИО, должность, email, рабочий телефон, добавочный телефон, мобильный телефон. Поля ФИО, должность, email и рабочий телефон ДОЛЖНЫ (MUST) быть обязательными (HTML5-атрибут `required`) и помечаться индикатором обязательности — звёздочкой `*` в подписи поля. Звёздочка ДОЛЖНА (MUST) отображаться красным цветом, отличным от цвета текста подписи, и НЕ ДОЛЖНА (MUST NOT) быть частью текста подписи (рисуется стилями, чтобы не зачитывалась скринридерами как часть имени поля — обязательность сообщает атрибут `required`). Поле email ДОЛЖНО (MUST) иметь тип `email`, поля телефонов — тип `tel`.

Предзаполненные значения полей email и рабочего телефона ДОЛЖНЫ (MUST) читаться из переменных окружения `FORM_EMAIL_DEFAULT` и `FORM_WORK_PHONE_DEFAULT` (загружаемых из файла `.env` при его наличии). Если переменная не задана, система ДОЛЖНА (MUST) использовать встроенные демо-значения по умолчанию (`@roga-i-kopyta.com` и `+7(800)000-00-00`). Предзаполненные значения ДОЛЖНЫ (MUST) отображаться при открытии главной страницы (GET `/`).

После отправки формы (POST `/generate`) — как при успешной генерации (HTTP 200), так и при ошибке валидации (HTTP 400) — все поля формы ДОЛЖНЫ (MUST) отображать значения, введённые пользователем в этом запросе («липкая форма», sticky form). Введённые значения ДОЛЖНЫ (MUST) иметь приоритет над предзаполненными значениями по умолчанию для полей email и рабочего телефона. Необязательные поля, оставленные пустыми, ДОЛЖНЫ (MUST) оставаться пустыми после отправки. Система НЕ ДОЛЖНА (MUST NOT) сохранять введённые значения между запросами иначе как в ответе на текущий POST: при повторном открытии страницы (GET `/`, включая перезагрузку) форма ДОЛЖНА (MUST) показывать значения по умолчанию, как при первом визите.

Заглушка «Здесь появится ваш QR-код» в области предпросмотра ДОЛЖНА (MUST) располагаться на одном вертикальном уровне с надписью «Заполните форму» над формой: обе надписи являются первыми элементами своих колонок без дополнительных верхних отступов у одной из них.

#### Scenario: Открытие главной страницы

- **WHEN** пользователь открывает главную страницу приложения
- **THEN** отображается форма с шестью полями и подсказкой, какие поля обязательны, а в области предпросмотра — заглушка «Здесь появится ваш QR-код»

#### Scenario: Красный индикатор обязательности

- **WHEN** пользователь открывает главную страницу приложения
- **THEN** у подписей обязательных полей (ФИО, должность, email, рабочий телефон) отображается красная звёздочка, а у подписей необязательных полей (добавочный и мобильный телефон) звёздочки нет

#### Scenario: Заглушка предпросмотра на одном уровне с заголовком формы

- **WHEN** пользователь открывает главную страницу приложения (QR-код ещё не сгенерирован)
- **THEN** надписи «Заполните форму» (левая колонка) и «Здесь появится ваш QR-код» (правая колонка) начинаются на одном вертикальном уровне

#### Scenario: Отправка формы без обязательного поля

- **WHEN** пользователь пытается отправить форму, не заполнив обязательное поле
- **THEN** браузер блокирует отправку и указывает на незаполненное поле (встроенная HTML5-валидация)

#### Scenario: Предзаполненные значения из .env

- **WHEN** в `.env` заданы `FORM_EMAIL_DEFAULT` и `FORM_WORK_PHONE_DEFAULT` и пользователь открывает форму (GET `/`)
- **THEN** поля email и рабочего телефона предзаполнены значениями из `.env`

#### Scenario: Предзаполненные значения без .env

- **WHEN** файл `.env` отсутствует и пользователь открывает форму (GET `/`)
- **THEN** поля email и рабочего телефона предзаполнены встроенными демо-значениями

#### Scenario: Введённые значения сохраняются после генерации

- **WHEN** пользователь заполнил форму и успешно сгенерировал QR-код (HTTP 200)
- **THEN** все поля формы отображают введённые пользователем значения (ФИО, должность, email, рабочий, добавочный и мобильный телефоны) рядом с предпросмотром QR-кода

#### Scenario: Введённое значение приоритетнее дефолта

- **WHEN** пользователь изменил предзаполненные email и рабочий телефон на свои значения и отправил форму
- **THEN** после перерисовки страницы в этих полях отображаются значения пользователя, а не значения по умолчанию из `.env`

#### Scenario: Пустые необязательные поля остаются пустыми

- **WHEN** пользователь отправил форму с пустыми добавочным и мобильным телефонами
- **THEN** после перерисовки страницы эти поля остаются пустыми

#### Scenario: Перезагрузка страницы возвращает дефолты

- **WHEN** пользователь сгенерировал QR-код, а затем перезагрузил страницу (GET `/`)
- **THEN** поля email и рабочего телефона снова показывают значения по умолчанию, остальные поля пусты

### Requirement: Серверная валидация данных формы

Система ДОЛЖНА (SHALL) проверять данные формы на сервере при POST `/generate` до начала генерации: поля ФИО, должность, email и рабочий телефон ДОЛЖНЫ (MUST) быть заполнены (непустые после удаления пробельных символов по краям), поле email ДОЛЖНО (MUST) соответствовать формату `текст@текст.текст`. Поля добавочного и мобильного телефонов НЕ ДОЛЖНЫ (MUST NOT) требоваться.

При наличии ошибок система ДОЛЖНА (SHALL): не генерировать QR-код, вернуть статус HTTP 400 и отобразить страницу с формой и человекочитаемым сообщением обо всех найденных ошибках. Поля формы при этом ДОЛЖНЫ (MUST) отображать введённые пользователем значения (включая невалидные), чтобы пользователь исправлял только проблемные поля. Запрос с невалидными данными НЕ ДОЛЖЕН (MUST NOT) приводить к ошибке HTTP 500.

#### Scenario: Отправка без обязательного поля

- **WHEN** приходит POST `/generate` без поля «ФИО» (или с пустым значением)
- **THEN** система возвращает HTTP 400 и страницу с сообщением об ошибке, QR-код не генерируется

#### Scenario: Некорректный email

- **WHEN** приходит POST `/generate` с email, не содержащим `@` или доменную часть
- **THEN** система возвращает HTTP 400 и страницу с сообщением об ошибке

#### Scenario: Введённые значения сохраняются при ошибке валидации

- **WHEN** приходит POST `/generate` с заполненными ФИО и должностью, но некорректным email
- **THEN** система возвращает HTTP 400, а поля формы (включая некорректный email) отображают введённые значения

#### Scenario: Валидные данные с пустыми необязательными полями

- **WHEN** приходит POST `/generate` с заполненными обязательными полями и пустыми добавочным/мобильным телефонами
- **THEN** система возвращает HTTP 200 и страницу с предпросмотром QR-кода

#### Scenario: Сообщение содержит все ошибки

- **WHEN** приходит POST `/generate` с несколькими невалидными полями (пустое ФИО и некорректный email)
- **THEN** сообщение об ошибке перечисляет все проблемные поля, а не только первое
