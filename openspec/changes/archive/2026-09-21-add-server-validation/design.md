# Design: add-server-validation

## Context

`generate_card()` читает `request.form['name']` и т.д. напрямую — отсутствие ключа даёт `KeyError` → HTTP 500. Шаблон `index.html` уже содержит блок `{% if error %}`, который никогда не использовался. См. proposal.md — Why.

## Goals / Non-Goals

**Goals:**

- Ни один запрос к `/generate` не приводит к 500 из-за данных формы.
- Пользователь видит понятное сообщение, какие поля заполнить/исправить.
- Валидация покрыта тестами.

**Non-Goals:**

- Сохранение введённых значений при ошибке, валидация телефонов по маске, RFC-email.

## Decisions

1. **Отдельная функция `validate_form(form) -> list[str]`.**
   Возвращает список текстов ошибок (пустой — всё ок). Чистая функция — легко тестировать без Flask-контекста. `generate_card()` вызывает её первой строкой; при ошибках — `render_template('index.html', error=...)`, статус 400.
   _Альтернатива:_ библиотека (WTForms, marshmallow) — отвергнута, overkill для шести полей и одного эндпоинта.

2. **Правила:**
   - `name`, `job_title`, `work_phone` — обязательные, непустые после `strip()`.
   - `email` — обязательный + простой regex `^[^@\s]+@[^@\s]+\.[^@\s]+$`.
   - `ext_phone`, `mobile` — необязательные, без проверок.
   Ошибки собираются все сразу (а не первая попавшаяся) — пользователь видит полный список.

3. **Чтение полей через `request.form.get(..., "")`.**
   Убирает `KeyError` как класс ошибки; отсутствующее поле = пустая строка = ошибка валидации для обязательных.

4. **Статус 400 при ошибке, страница с формой.**
   Не редирект и не JSON: приложение — одна страница, рендерим её же с блоком `error`.
   _Альтернатива:_ 200 с сообщением — отвергнута, семантически это клиентская ошибка.

## Risks / Trade-offs

- [Простой regex email пропустит экзотику (`a@b.c`)] → Принято: осознанный компромисс, полный RFC — избыточен; цель — отсечь опечатки.
- [Пользователь потеряет введённые данные при ошибке] → Смягчение: ошибок не будет при обычном сценарии (HTML5-валидация на клиенте остаётся первой линией); сохранение значений — отдельное улучшение.

## Migration Plan

Не требуется: валидные запросы работают как раньше. Откат — revert коммита.
