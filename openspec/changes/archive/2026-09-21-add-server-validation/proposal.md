# Proposal: add-server-validation

## Why

Сейчас ввод проверяется только HTML5-атрибутами на клиенте — их легко обойти (curl, старый браузер, отключённый JS). POST `/generate` без обязательного поля падает с `KeyError` (HTTP 500), а некорректный email молча попадает в vCard. Нужна серверная проверка с человекочитаемыми ошибками.

## What Changes

- В `generate_card()` добавляется серверная валидация: обязательные поля не пустые (ФИО, должность, email, рабочий телефон), email соответствует простому формату.
- При ошибках валидации страница перерисовывается с сообщением об ошибке (блок `error-message` уже есть в шаблоне) и статусом HTTP 400, QR-код не генерируется.
- Добавляются тесты на валидацию (400 на пустое поле, 400 на кривой email, 200 на валидные данные).

## Capabilities

### New Capabilities

_(пусто)_

### Modified Capabilities

- `web-interface`: POST `/generate` с невалидными данными больше не падает с 500 — возвращает 400 и страницу с сообщением об ошибке; добавляется требование серверной валидации.

## Impact

- **Код:** `app.py` — функция валидации + её вызов в `generate_card()`.
- **Тесты:** `tests/test_app.py` — новые тесты на ошибки валидации.
- **Версия:** 1.1.1 → 1.2.0 (новое поведение, обратно совместимо для валидных запросов).

## Не входит в объём (Non-goals)

- Сохранение введённых значений в форме после ошибки (пользователь вернётся кнопкой браузера).
- Строгая валидация телефонов по маске (форматы различаются; проверяем только непустоту обязательного).
- Валидация на клиенте до отправки (отдельный пункт backlog, п.4).
- Полная RFC-совместимая проверка email — достаточно простого формата.
