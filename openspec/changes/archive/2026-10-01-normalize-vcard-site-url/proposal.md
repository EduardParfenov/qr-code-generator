# Пункт бэклога «Добавлять схему в поле URL vCard» закрывался на неверных данных — сначала нужно уточнить формулировку

## Why

Пункт бэклога утверждал: «сейчас в vCard попадает `URL:www.gipvn.ru` без схемы».
Проверка показала, что это уже не так — текущий `COMPANY_SITE` содержит
`https://www.gipvn.ru`, и в работающем контейнере vCard содержит схему. Дефект
переехал: он остался в двух других местах, которые бэклог не называл — в
дефолте `app.py:86` (`'roga-i-kopyta.com'`) и в `.env.example:9`.

Исходная цель пункта сохраняется: RFC 2426 требует в поле `URL` полный URI, а
`www.gipvn.ru` им не является. Часть клиентов покажет такой адрес текстом, а не
ссылкой, и пользователь отсканирует QR-код впустую. Сейчас это не происходит
только потому, что конкретный администратор записал схему вручную в `.env`, а
`.env` в git не отслеживается — у следующего администратора, развернувшего
приложение по инструкции из `DEPLOY.md`, дефект проявится.

## What Changes

- В `generate_vcard()` (`app.py`) значение поля `URL` приводится к полному URI:
  если в `COMPANY_SITE` нет схемы, она добавляется. Схема, уже указанная
  администратором (`http://`, `https://` и любые другие), сохраняется как есть —
  приложение не переписывает то, что решает владелец конфигурации.
- **BREAKING (для содержимого vCard):** при `COMPANY_SITE` без схемы содержимое
  поля `URL` меняется — теперь появляется `https://`. Требуемые в vCard
  закодированные байты меняются, то есть QR-код для той же визитки будет другим.
- Демо-значение по умолчанию в `app.py:86` меняется на `https://roga-i-kopyta.com`,
  то же в `.env.example` — чтобы развёртывание по инструкции сразу давало валидный
  URI.
- Пустое значение `COMPANY_SITE` (`COMPANY_SITE=` в `.env`) обрабатывается явно:
  поле `URL` остаётся пустым, схема к пустой строке не добавляется.
- `readme.md` (раздел «Настройка») и `DEPLOY.md` (шаг «Настроить .env»):
  указывается, что `COMPANY_SITE` задаётся со схемой и что приложение подставит
  `https://`, если её нет.
- Пункт бэклога «Добавлять схему в поле `URL` vCard» переписывается под
  фактическое состояние и закрывается этим change.
- Версия 2.7.0 → 2.8.0: содержимое vCard меняется, но не набор полей и не
  формат — по правилам проекта это minor.

## Capabilities

### New Capabilities

_(пусто)_

### Modified Capabilities

- `vcard-generation`: появляется требование о том, что поле `URL` ДОЛЖНО содержать
  полный URI — со схемой, добавленной приложением при её отсутствии в
  `COMPANY_SITE`; отдельно оговаривается поведение для пустого значения и то,
  что уже указанная схема не переписывается. Существующее требование о том, что
  сайт читается из `COMPANY_SITE`, и требование round-trip не меняются.

## Impact

- **Код:** `app.py`, функция `generate_vcard()` — появляется нормализация значения
  `URL` и константа с дефолтом. Роуты, валидация формы, генерация QR и логирование
  не затрагиваются.
- **Конфигурация:** `.env.example:9` — демо-значение получает схему. `.env`
  пользователя не меняется и не коммитится; правильный `https://` в нём уже есть.
- **Тесты:** `tests/test_app.py` — константа `DEFAULT_COMPANY_SITE` и два теста,
  проверяющие старое поведение без схемы, требуют правки; добавляются тесты на
  нормализацию (без схемы, со схемой, пустое значение, не-HTTP схема).
- **Документация:** `readme.md` (раздел «Настройка»), `DEPLOY.md` (шаг 3), `backlog.md`.
- **Пользовательский эффект:** QR-код для визитки меняется, если `COMPANY_SITE`
  задан без схемы; адрес в контакте на телефоне становится ссылкой вместо текста.
  При `COMPANY_SITE` со схемой ничего не меняется, включая побайтово.
- **Совместимость:** требование round-trip по кириллице в `URL` не нарушается —
  добавление схемы не меняет ни набор символов домена, ни его кодировку. Проверено:
  `vobject` сериализует и разбирает значения с кириллицей и без схемы без потерь,
  то есть нормализация целиком выполняется на стороне приложения.
- **Зависимости:** не добавляются. Разбор схемы — регулярное выражение по
  RFC 3986, стандартная библиотека.
- **Приватность:** не затрагивается — в логи по-прежнему пишется полный текст vCard
  (см. отдельный пункт бэклога про ПДн).

## Не входит в объём (Non-goals)

- **Кириллические домены (IDN) и punycode.** `COMPANY_SITE=рога-и-копыта.рф`
  получит `https://`, но для соответствия RFC домен должен быть приведён к
  punycode (`xn--80akhbyknj4f.xn--p1ai`). Это отдельная задача: имена
  нечитаемы, а решение требует выбора способа конвертации. Здесь фиксируется как
  известная граница; отдельный тест подтверждает, что кириллица в домене
  переживает round-trip вместе с добавленной схемой.
- **Проверка достижимости сайта** (HTTP-запрос, DNS). Приложение не ходит в сеть при
  генерации vCard, и менять это нельзя: генерация перестала бы работать без
  интернета.
- **Нормализация прочих полей vCard** — `EMAIL` с той же проблемой схемы не имеет
  (адрес почты не URI), `TEL` схемы не требует.
- **Изменение формата vCard на 4.0**, где `URL` объявлен обязательным: это ломает
  совместимость со старыми телефонами, что уже отмечено в пункте про `CHARSET`.
- **Правка пунктов бэклога про ПДн в логах и модель доступа** — они решаются
  отдельными change.
- **Миграция `COMPANY_SITE` в существующих `.env`.** Файл не отслеживается git, а
  приложение теперь приводит значение к URI само, поэтому ручная правка
  конфигурации не требуется для корректности.
