## ADDED Requirements

### Requirement: Контейнер сообщает работоспособность

Контейнер приложения ДОЛЖЕН (SHALL) сообщать работоспособность через механизм
health check Docker: Docker ДОЛЖЕН (MUST) периодически опрашивать приложение
изнутри контейнера, а вывод `docker ps` ДОЛЖЕН (MUST) отражать результат
последней проверки как `(healthy)` или `(unhealthy)`. Проверка ДОЛЖНА (MUST)
выполняться по адресу `127.0.0.1` на порту приложения внутри контейнера,
без публикации порта на хост: наружу по-прежнему смотрят только порты nginx.
Проверка ДОЛЖНА (MUST) обращаться к уже существующему маршруту приложения —
дополнительные маршруты и публичные URL для целей проверки НЕ ДОЛЖНЫ (MUST NOT)
добавляться. Выполнение проверки НЕ ДОЛЖНО (MUST NOT) изменять логи приложения:
доступные администратору логи остаются каналом аудита vCard.

#### Scenario: Работающее приложение отмечено как работоспособное

- **WHEN** контейнер запущен и приложение отвечает на HTTP-запросы
- **THEN** вывод `docker ps` показывает для контейнера статус `(healthy)`

#### Scenario: Не отвечающий процесс виден как нездоровый

- **WHEN** контейнер запущен, но приложение не отвечает на HTTP-запросы
  (процесс не завершился, но завис)
- **THEN** вывод `docker ps` показывает для контейнера статус `(unhealthy)`,
  хотя контейнер не завершён и отображается как работающий

#### Scenario: Порт приложения остаётся недоступен на хосте

- **WHEN** выполняется проверка работоспособности
- **THEN** проверка обращается к приложению изнутри контейнера, а порт 8000
  остаётся недоступен с хоста — принцип «наружу смотрит только nginx» сохраняется

#### Scenario: Логи приложения не засоряются проверкой

- **WHEN** проверка работоспособности выполняется многократно
- **THEN** в выводе `docker compose logs` не появляется записей о самой проверке,
  а записи о созданных vCard остаются единственными данными приложения в логах

#### Scenario: Вывод отражает только текущее состояние

- **WHEN** контейнер был нездоров, а затем приложение восстановилось
- **THEN** вывод `docker ps` показывает `(healthy)`, и провал прошлых проверок
  в этом выводе не сохраняется — хранение истории проверок не требуется
