## Purpose

Формирование контакта в формате vCard из данных, введённых пользователем в форму, для последующего кодирования в QR-код и сохранения в адресную книгу смартфона.

## ADDED Requirements

### Requirement: Формирование vCard из данных формы

Система ДОЛЖНА (SHALL) формировать vCard, включающую: ФИО (FN), должность вместе с названием организации (TITLE), email (EMAIL), рабочий телефон (TEL тип WORK), добавочный телефон (TEL тип WORK), мобильный телефон (TEL тип CELL), сайт компании (URL) и рабочий адрес компании (ADR тип WORK).

Название организации, сайт и адрес компании являются настройками приложения и задаются в коде (см. readme, раздел «Настройка»).

#### Scenario: Генерация vCard с полным набором данных

- **WHEN** пользователь отправляет форму с заполненными полями: ФИО, должность, email, рабочий телефон, добавочный телефон, мобильный телефон
- **THEN** система формирует валидную vCard, содержащую все перечисленные данные, при этом должность дополняется названием организации

#### Scenario: Генерация vCard с обязательными полями

- **WHEN** пользователь отправляет форму с заполненными обязательными полями (ФИО, должность, email, рабочий телефон) и пустыми необязательными (добавочный, мобильный)
- **THEN** система формирует vCard с обязательными данными; поля добавочного и мобильного телефонов присутствуют в vCard даже если пусты

### Requirement: Логирование созданных vCard

Система ДОЛЖНА (SHALL) записывать сериализованное содержимое каждой созданной vCard в лог-файл `logs/info.log` с уровнем INFO, меткой времени и кодировкой UTF-8.

#### Scenario: Запись vCard в лог

- **WHEN** система успешно сформировала vCard по данным формы
- **THEN** в `logs/info.log` появляется запись уровня INFO с полным текстом vCard

### Requirement: Автоматическое создание директории логов

Система ДОЛЖНА (SHALL) при запуске создавать директорию `logs/`, если она отсутствует (директория исключена из git и не существует в свежем клоне репозитория). Запуск приложения НЕ ДОЛЖЕН завершаться ошибкой из-за отсутствия директории логов.

#### Scenario: Запуск без директории логов

- **WHEN** приложение запускается при отсутствующей директории `logs/`
- **THEN** директория создаётся автоматически, приложение стартует без ошибок, а лог-файл `logs/info.log` создаётся при первой записи
