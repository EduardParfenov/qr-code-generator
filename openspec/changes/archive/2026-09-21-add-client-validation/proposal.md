# Proposal: add-client-validation

## Why

Серверная валидация (v1.2.0) отсекает ошибки, но пользователь узнаёт о них только после отправки формы и перезагрузки страницы. Маски ввода телефонов и проверка email до отправки сократят число ошибок и сделают форму удобнее: номер форматируется автоматически, опечатка в email видна сразу.

## What Changes

- В `static/main.js` добавляется клиентская валидация:
  - маски ввода телефонов: рабочий и мобильный автоформатируются как `+7(XXX)XXX-XX-XX` при вводе; добавочный — только цифры и дефис;
  - проверка email при отправке: при несоответствии формату отправка блокируется, сообщение об ошибке показывается сразу, без перезагрузки страницы.
- В `templates/index.html` добавляется блок для клиентских сообщений об ошибках (стиль `error-message` уже существует).
- Серверная валидация и HTML5-атрибуты остаются — клиентская проверка их дополняет, а не заменяет.

## Capabilities

### New Capabilities

_(пусто)_

### Modified Capabilities

- `web-interface`: форма получает маски ввода телефонов и проверку email до отправки с мгновенным сообщением об ошибке без перезагрузки страницы.

## Impact

- **Код:** `static/main.js` (маски, обработчик submit), `templates/index.html` (блок ошибок для JS).
- **Код приложения (`app.py`):** не затрагивается.
- **Версия:** 1.2.0 → 1.3.0 (новое пользовательское поведение).

## Не входит в объём (Non-goals)

- JS-фреймворки и библиотеки масок (IMask.js и т.п.) — только чистый JS без зависимостей, приложение должно работать офлайн.
- Юнит-тесты JS (в проекте нет JS-тестовой инфраструктуры; проверка — ручная, backend защищён серверными тестами).
- Строгая серверная проверка телефонов по маске (сервер по-прежнему требует только непустой рабочий телефон).
- Сохранение введённых значений после серверной ошибки.
