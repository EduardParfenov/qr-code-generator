# Design: add-client-validation

## Context

`static/main.js` содержит одну неиспользуемую функцию (`copyImageFallback`). Форма в `index.html` имеет HTML5-атрибуты (`required`, `type=email/tel`). Серверная валидация есть (v1.2.0). См. proposal.md — Why.

## Goals / Non-Goals

**Goals:**

- Телефон форматируется по мере ввода, без ручного расставления скобок/дефисов.
- Ошибка email видна до отправки, страница не перезагружается.
- Ноль внешних зависимостей, работа офлайн.

**Non-Goals:**

- Библиотеки масок, JS-тесты, строгая проверка числа цифр на сервере.

## Decisions

1. **Чистый JS в `static/main.js`, без библиотек.**
   Внутренний инструмент, возможна работа без интернета — CDN-зависимость (IMask.js) неприемлема. Маски простые, пишутся руками за ~40 строк.
   _Альтернатива:_ IMask.js с CDN — отвергнута (офлайн + философия «без фреймворков»).

2. **Маска телефона `+7(XXX)XXX-XX-XX`: форматирование из цифр.**
   Из введённого извлекаются цифры (ведущие `7`/`8` нормализуются в код страны `+7` при 11 цифрах), результат собирается в шаблон по мере набора. Применяется к `work_phone` и `mobile`. `ext_phone` — фильтр: только цифры и дефис (короткий внутренний номер).
   Ограничение: маска заточена под российский формат — осознанно, контекст приложения российский (дефолты `+7(...)`).
   **Найденные при реализации тонкости** (проверяются симуляцией посимвольного ввода и удаления):
   - обработчик `input` получает уже отформатированное значение, поэтому маска сначала убирает собственный префикс `+7(` — иначе он накапливается в цифрах номера;
   - код страны отбрасывается только при 11 цифрах — иначе ломаются номера с кодом 800;
   - закрывающая скобка добавляется только при наличии 4-й цифры — иначе она «восстанавливается» при удалении и поле нельзя очистить.

3. **Email проверяется на submit тем же форматом, что на сервере** (`текст@текст.текст`). Несоответствие → `preventDefault()`, сообщение в блоке `#js-error` (класс `error-message`, скрыт по умолчанию), фокус в поле email.
   _Альтернатива:_ `alert()` — отвергнут, неконсистентно с серверными сообщениями.

4. **Клиентская валидация — дополнение, не замена.**
   HTML5-атрибуты и серверная валидация остаются нетронутыми: при отключённом JS форма работает как сейчас.

## Risks / Trade-offs

- [Маска не подойдёт для международных номеров] → Принято: целевая аудитория — российские номера; необходимые цифры маска не отрезает (больше 11 цифр — остаток игнорируется при форматировании, но сервер не ограничивает).
- [JS без тестов — регрессия незаметна] → Смягчение: backend покрыт тестами; JS-логика минимальна; ручная проверка в задачах.
- [Предзаполненное значение `FORM_WORK_PHONE_DEFAULT` (`+7(800)000-00-00`) конфликтует с маской] → При загрузке маска применяется к существующему значению (нормализует его).

## Migration Plan

Не требуется: изменения только на клиенте, обратная совместимость полная. Откат — revert коммита.
