# Предложение: переход на развертывание в Docker

## Why

Сейчас приложение разворачивается вручную: на сервере создаётся venv, ставятся
зависимости, приложение запускается через `python app.py` — встроенным
dev-сервером Flask, который не предназначен для production (однопоточный,
без гарантий безопасности). На целевом физическом сервере уже работает nginx
и планируется размещать несколько проектов — нужен воспроизводимый,
изолированный способ развертывания, который не зависит от окружения сервера
и корректно встраивается за nginx как reverse proxy.

## What Changes

- Добавляется **Dockerfile** на базе `python:3.11-slim`: установка
  зависимостей из `requirements.txt`, копирование кода, запуск через
  **gunicorn** (2 worker-процесса по умолчанию, настраивается через
  переменную окружения), прослушивание порта **8000** внутри контейнера.
- Добавляется **gunicorn** в `requirements.txt`.
- Добавляется **`.dockerignore`**: из контекста сборки исключаются `.venv/`,
  `logs/`, `.env`, `input/`, `.git/`, `__pycache__/`, `.pytest_cache/`.
- Добавляется **`docker-compose.yml`**: декларативное описание запуска
  (стабильное имя контейнера, общая сеть с nginx без публикации порта на
  хост, `env_file`, restart-политика, ротация логов Docker) — ради удобства
  и воспроизводимости команды запуска.
- **Конфигурация** в контейнере — через переменные окружения
  (`env_file` в compose / `docker run --env-file`); файл `.env` не вшивается
  в образ. Существующие переменные (`COMPANY_*`, `FORM_*`, `CARD_TEMPLATE_URL`)
  работают без изменений.
- **Логи — только stdout (BREAKING для способа чтения логов)**: приложение
  перестаёт писать в `logs/info.log`; файловый обработчик с ротацией и
  автосоздание директории `logs/` удаляются из кода. Логи смотрятся через
  `docker logs` / `docker compose logs`, ротацией заведует Docker
  (logging driver json-file, настраивается в compose). Так же, как и у
  других проектов на сервере, — ради однообразия.
- В **CI** (GitHub Actions) добавляется шаг «собрать Docker-образ» после
  тестов — без публикации в registry.
- **Локальная разработка не меняется**: `python app.py` с dev-сервером,
  `.env`, `FLASK_DEBUG`/`FLASK_HOST`/`FLASK_PORT` работают как раньше.
- Обновляются `readme.md` (раздел «Запуск в Docker» с примером `docker build`,
  `docker run` и конфигурации nginx `proxy_pass`) и `AGENTS.md`.
- Выполняется релизная рутина: обновляются `VERSION` и `CHANGELOG.md`.

## Capabilities

### New Capabilities

- `docker-deployment`: сборка и запуск приложения в Docker-контейнере —
  Dockerfile, запуск через gunicorn, передача конфигурации через переменные
  окружения, доступ к логам (stdout + volume), пример интеграции с nginx
  reverse proxy.

### Modified Capabilities

- `vcard-generation`: требование «Логирование созданных vCard» изменяется —
  запись в stdout вместо файла `logs/info.log` с ротацией; требование
  «Автоматическое создание директории логов» удаляется.

## Не входит в объём (Non-goals)

- **Публикация образа в registry** (ghcr.io и др.): образ собирается на
  сервере из исходников, CI только проверяет сборку.
- **Система сбора логов** (Loki, ELK, journald-драйвер): логи читаются
  штатным `docker logs`, настройка централизованного сбора — отдельная задача.
- Настройка nginx на физическом сервере — даётся только пример конфигурации
  в документации, реальный конфиг сервера вне репозитория.
- Изменение поведения приложения (роуты, валидация, генерация vCard/QR) —
  функциональность остаётся прежней.
- HTTPS/TLS — терминируется nginx на хосте, контейнер работает по HTTP.

## Impact

- **Новые файлы:** `Dockerfile`, `.dockerignore`, `docker-compose.yml`.
- **Изменяемые файлы:** `requirements.txt` (+ gunicorn), `app.py`
  (логирование только в stdout: удалены `RotatingFileHandler` и создание
  `logs/`), `readme.md`, `AGENTS.md`, `VERSION`, `CHANGELOG.md`,
  `.github/workflows/ci.yml` (шаг сборки образа).
- **Зависимости:** + `gunicorn` (production WSGI-сервер).
- **Развертывание:** основной способ для прода — Docker-контейнер за nginx
  reverse proxy (запуск через `docker compose up -d`). Локальный запуск
  `python app.py` сохраняется.
- **Логи:** файл `logs/info.log` больше не ведётся; логи — в stdout
  (`docker logs`), ротация — средствами Docker.
- **Тесты:** тест ротации логов заменяется на тест логирования в stdout.
