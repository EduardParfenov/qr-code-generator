# Дельта: vcard-generation (dockerize-deployment)

## MODIFIED Requirements

### Requirement: Логирование созданных vCard

Система ДОЛЖНА (SHALL) записывать сериализованное содержимое каждой созданной
vCard в стандартный поток вывода (stdout) с уровнем INFO, меткой времени и
кодировкой UTF-8, чтобы логи были доступны через `docker logs` /
`docker compose logs` при запуске в контейнере и через консоль при локальном
запуске. Запись в лог-файл и ротация логов на стороне приложения НЕ
выполняются: ротацией логов заведует Docker (logging driver).

#### Scenario: Запись vCard в лог

- **WHEN** система успешно сформировала vCard по данным формы
- **THEN** в stdout появляется запись уровня INFO с полным текстом vCard

#### Scenario: Просмотр логов в контейнере

- **WHEN** приложение запущено в Docker-контейнере и создана vCard
- **THEN** запись видна в выводе `docker logs <контейнер>` /
  `docker compose logs` с меткой времени

#### Scenario: Ротация при переполнении

- **WHEN** объём логов достигает предела, заданного в настройках logging
  Docker (в `docker-compose.yml`)
- **THEN** Docker ротирует лог-файлы (старые архивируются, лишние удаляются);
  приложение ротацию не выполняет и о ней не знает

## REMOVED Requirements

### Requirement: Автоматическое создание директории логов

**Reason**: Приложение перешло на логирование только в stdout (docker logs);
файл `logs/info.log` больше не ведётся, директория `logs/` приложению не
нужна. Ротация логов делегирована Docker (logging driver), что
соответствует принятой практике и даёт однообразие с другими проектами
на сервере.

**Migration**: Логи смотрятся через `docker logs <контейнер>` /
`docker compose logs -f` (при локальном запуске — в консоли). Для выгрузки
аудита: `docker logs <контейнер> > audit.txt`. Архивы старых `logs/info.log*`
на сервере сохраняются как есть, новых записей в них не будет.
