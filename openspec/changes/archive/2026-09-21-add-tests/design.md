# Design: add-tests

## Context

`app.py` — один модуль: три чистые функции (`generate_vcard`, `generate_qr_code`, `create_business_card`) и два роута. Импорт `app` имеет побочные эффекты: `load_dotenv()`, создание `logs/`, настройка логирования — это допустимо для тестов. См. proposal.md — Why.

## Goals / Non-Goals

**Goals:**

- `pytest` запускается из корня проекта одной командой и проходит зелёным.
- Покрыты: формирование vCard (поля, типы телефонов, данные компании из env-дефолтов), генерация QR (PIL-изображение), композиция с фоном, оба роута (200, предпросмотр с base64).
- Тесты не зависят от локального `.env` разработчика.

**Non-Goals:**

- Изоляция/моки файловой системы ради чистоты (лог в `logs/info.log` при тестах допустим).
- Параметризованные/property-based тесты, coverage-отчёты, CI.

## Decisions

1. **pytest, dev-зависимости в `requirements-dev.txt`.**
   Боевые зависимости (`requirements.txt`) не раздуваем: тесты нужны только разработчику.
   _Альтернатива:_ добавить pytest в `requirements.txt` — отвергнута, в проде тесты не нужны.

2. **Структура: `tests/test_app.py` + пустой `conftest.py` в корне.**
   Наличие `conftest.py` в корне заставляет pytest добавить корень в `sys.path` — `import app` работает без хаков с путями. Один файл тестов: проект мал, разбивка излишня.

3. **Flask-роуты тестируем через `app.test_client()`.**
   Штатный способ Flask: без поднятия сервера, быстро, проверяет и статус, и содержимое ответа (base64-картинка, имя в ответе).

4. **Независимость от `.env`: monkeypatch/очистка переменных в фикстуре.**
   Тесты на дефолты удаляют `COMPANY_*` из окружения (через `monkeypatch.delenv`), тест на чтение из env — устанавливает переменную (`monkeypatch.setenv`) и проверяет, что она попала в vCard. Локальный `.env` разработчика не должен валить тесты.
   Нюанс: `QR_X_POS` и т.п. читаются на уровне модуля при импорте — тесты не полагаются на их значения, проверяют только тип/размер результата.

5. **Что проверяем в vCard: содержимое сериализованной строки.**
   `FN`, `TITLE` (с названием организации), `EMAIL`, `TEL;TYPE=WORK`, `TEL;TYPE=CELL`, `URL`, `ADR` — по подстрокам; плюс обратный парсинг через `vobject.readOne` как проверка валидности.

## Risks / Trade-offs

- [Импорт `app` пишет в `logs/info.log` при тестах] → Принято: безобидно, папка в `.gitignore`.
- [Тесты на дефолты сломаются, если изменятся демо-значения] → Осознанно: тест фиксирует контракт дефолтов; меняем дефолт — правим тест.
- [`.env` разработчика может повлиять] → Фикстуры с `monkeypatch` снимают зависимость.

## Migration Plan

```bash
pip install -r requirements-dev.txt
python -m pytest
```

Откат: удалить `tests/`, `conftest.py`, `requirements-dev.txt`.
