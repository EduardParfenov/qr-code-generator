# Дизайн: красные звёздочки обязательных полей

## Context

В `templates/index.html` звёздочки обязательных полей «зашиты» в текст подписей (`<label>Ф.И.О.*</label>` и т.д.), поэтому наследуют зелёный цвет `label` (#009639). Стили — в `static/style.css`, цветовая схема задана переменными в `:root`. Мотивация — см. proposal.md.

## Goals / Non-Goals

**Goals:**
- Красная звёздочка у обязательных полей, управляемая из одного места (CSS).
- Звёздочка не входит в текст подписи (доступность: обязательность сообщает `required`).

**Non-Goals:**
- Легенда `.attention`, backend, JS, логика валидации — без изменений (см. proposal.md, «Не входит в объём»).

## Decisions

### 1. Способ: CSS `::after` у `label.required`, звёздочки убрать из текста

В HTML символ `*` удаляется из подписей, подписям обязательных полей добавляется класс `required`; в CSS правило `label.required::after { content: '*'; ... }` рисует красную звёздочку.

Альтернативы:
- **`<span class="required-star">*</span>` вокруг существующих звёздочек** — явнее в разметке, но символ остаётся в тексте подписи (зачитывается скринридером) и требует больше правок в HTML.
- **`label:has(+ input[required])::after`** — ноль правок в HTML, но привязка к структуре DOM хрупкая: при смене порядка элементов правило молча перестанет работать.

Выбран первый вариант (согласовано с пользователем): чистый HTML, единая точка управления стилем, надёжная связь класса с полем.

### 2. Цвет — CSS-переменная `--required-color: #d32f2f` в `:root`

Красный `#d32f2f` согласован с пользователем; по тону близок к красному сообщений об ошибках (#c62828) и читается на белом фоне. Переменная — в духе существующей схемы (`--primary-color` и др.).

### 3. Легенда `.attention` не меняется

Блок «* - поля обязательные для заполнения» уже целиком красный — согласовано оставить как есть.

### 4. Выравнивание заглушки — убрать обёртку `.result`, а не добавлять CSS

Сдвиг вниз на 25px возникает из-за того, что в ветке `{% else %}` шаблона заглушка обёрнута в `<div class="result">` с `margin: 25px 0px`, тогда как в ветке с результатом надпись «Ваш QR-код, …» лежит вне `.result`. Решение — удалить обёртку в ветке `{% else %}`, повторив существующий паттерн ветки результата.

Альтернатива — CSS-переопределение (например, `.preview-section .result:first-child { margin-top: 0 }`) — отклонена: добавляет новое правило и класс-исключение там, где достаточно убрать лишний узел разметки; обёртка `.result` без содержимого всё равно давала бы лишние отступы.

### 5. Копирование — Clipboard API + `ClipboardItem`, без фолбэка

Кнопка «Копировать» (зелёная, как «Скачать») в существующем `.button-group`; обработчик в `main.js` (не inline `onclick`). Надписи кнопок действий центрированы по обеим осям (`display: flex; align-items: center; justify-content: center`) и не переносятся (`white-space: nowrap`). Изображение берётся из уже отображаемого `<img>` (data URL), конвертируется в Blob и записывается через `navigator.clipboard.write([new ClipboardItem({ 'image/png': blob })])`. Clipboard API доступен только в secure context (HTTPS или localhost) и только по жесту пользователя — клик по кнопке это условие выполняет.

Тултип «QR-скопирован в буфер» — `<span>` внутри кнопки, позиционируется абсолютно над ней, показывается/скрывается классом `show` (CSS transition), автоскрытие через `setTimeout` (~2 сек).

Фолбэк при недоступном API **не реализуем** — решение пользователя: в HTTP-развёртывании копирование доступно через нативное контекстное меню браузера (правый клик по изображению → «Копировать изображение»). При недоступном API обработчик молча выходит (guard clause), страница не ломается.

Заодно удаляется мёртвая функция `copyImageFallback()` из `main.js` (нигде не вызывается — остаток старой нереализованной попытки копирования).

Альтернативы:
- **Перехват `contextmenu` на кнопке** — отклонён пользователем после обсуждения: на кнопке нет нативного пункта «Копировать изображение», а в сценарии без Clipboard API перехват всё равно не поможет.
- **`document.execCommand('copy')`** — для изображений не работает (только текст), не рассматривается.

### 6. Выравнивание — единый `line-height` + flex-колонки с `margin: auto`, только десктоп

**Высота кнопок.** Разница высот возникала из-за того, что `<a>` («Скачать») наследует `line-height: 1.47059` от body, а `<button>` — браузерный `normal`. Эталон (кнопка «Сгенерировать QR-код») и кнопки действий получают единый `line-height: 1.47059` при одинаковых `padding`/`font-size` — высоты совпадают без магических пикселей и устойчивы к смене шрифта.

**Выравнивание рядов.** Grid-контейнер `.content-wrapper` уже растягивает обе колонки до одинаковой высоты. В медиа-запросе `@media (min-width: 969px)` (только двухколоночный макет) обе секции становятся flex-колонками: форма получает `flex: 1`, её submit — `margin-top: auto` (прижат к низу левой колонки); `.result` получает `flex: 1`, а изображение — `margin: auto 0` (auto-margin'и делят свободное место поровну — картинка центрируется между надписью и верхним рядом кнопок). У `.result` в этом медиа-запросе обнуляется нижний margin (`margin-bottom: 0`): исходный `margin: 25px 0` поднимал ряд кнопок правой колонки на 25px выше кнопки «Сгенерировать QR-код» (подтверждено замером `getBoundingClientRect` в headless Chrome: низ submit — 883px, низ ряда справа — 858px; после исправления — 883px = 883px). Ряды кнопок правой колонки остаются в потоке друг за другом — зазор 20px между ними не меняется. Мобильная вёрстка не затронута: до 969px новых правил нет.

Альтернативы:
- **Фиксированная высота кнопок в px** — хрупко при смене шрифта/отступов.
- **`justify-content: space-between` на секциях** — центрировать картинку между надписью и кнопками было бы нельзя, пришлось бы оборачивать элементы.

Побочный эффект (принимается): когда правая колонка выше левой и свободного места нет, зазор между картинкой и верхним рядом кнопок составляет 20px (margin-top `.button-group`) вместо прежних 52px.

## Risks / Trade-offs

- [Кто-то добавит новое обязательное поле и забудет класс `required`] → правило простое и задокументировано комментарием в CSS; при ревью видно несоответствие атрибуту `required`.
- [Звёздочка исчезнет из текста подписи при отключённом CSS] → обязательность по-прежнему обеспечивает HTML5-атрибут `required` (браузерная валидация работает без стилей).
- [В HTTP-развёртывании кнопка «Копировать» внешне «не работает» (без подсказки)] → осознанный trade-off, принят пользователем; нативное копирование через правый клик по изображению доступно всегда.
- [Персональные данные из vCard попадают в системный буфер обмена, доступный другим приложениям] → действие выполняется осознанно по клику пользователя; данных больше, чем уже показано на экране, не раскрывается.
