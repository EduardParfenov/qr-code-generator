# Design: configurable-card-template-link

## Context

В `templates/index.html` захардкожена ссылка `localfile:server\Брендбук\Визитка`. В `app.py` уже есть `context_processor` для значений формы (`FORM_EMAIL_DEFAULT` и т.п.) — готовый канал доставки настроек в шаблон. См. proposal.md — Why.

## Goals / Non-Goals

**Goals:**

- Адрес кнопки — из `CARD_TEMPLATE_URL`, без хардкода.
- Без переменной кнопка не рендерится (чистый интерфейс из коробки).
- Минимальный дифф, повторное использование существующего context processor.

**Non-Goals:**

- Валидация URL, настройка текста кнопки, несколько ссылок.

## Decisions

1. **`CARD_TEMPLATE_URL` в существующий `inject_form_defaults()` context processor.**
   Переменная читается при каждом рендере (`os.getenv`, дефолт `""`) — как её соседи по форме. Пустая строка в Jinja — falsy, условие `{% if card_template_url %}` скрывает блок.
   _Альтернатива:_ отдельный processor — отвергнута, излишне для одной переменной.

2. **Переменная закомментирована в `.env.example`.**
   Дефолт-опыт: кнопки нет. Кому нужно — раскомментирует и впишет свой адрес (http-ссылка или сетевой путь).

3. **Протокол ссылки не ограничиваем.**
   В исходном окружении это была сетевая папка, у других может быть http-ресурс. Браузерная безопасность (блокировка `file:`/`localfile:`) — вне зоны ответственности приложения.

## Risks / Trade-offs

- [Администратор впишет неработающий протокол и кнопка снова «не кликабельна»] → Принято: приложение честно рендерит то, что настроено; в `.env.example` — комментарий-подсказка.
- [XSS через `CARD_TEMPLATE_URL`] → Незначимо: значение задаёт администратор сервера, не пользователь; Jinja экранирует атрибут.

## Migration Plan

1. Обновиться до 2.2.0.
2. Кому нужна кнопка — добавить `CARD_TEMPLATE_URL=<адрес>` в `.env`.
3. Откат — revert коммита (вернётся нерабочая захардкоженная кнопка).
