# web-interface Specification

## Purpose
Веб-страница, через которую пользователь вводит контактные данные, запускает генерацию и получает готовое изображение с QR-кодом — с предпросмотром, скачиванием и печатью.

## Requirements

### Requirement: Форма ввода контактных данных

Система ДОЛЖНА (SHALL) отображать на главной странице (GET `/`) форму с полями: ФИО, должность, email, рабочий телефон, добавочный телефон, мобильный телефон. Поля ФИО, должность, email и рабочий телефон ДОЛЖНЫ (MUST) быть обязательными (помечены `*`, HTML5-атрибут `required`). Поле email ДОЛЖНО (MUST) иметь тип `email`, поля телефонов — тип `tel`.

Предзаполненные значения полей email и рабочего телефона ДОЛЖНЫ (MUST) читаться из переменных окружения `FORM_EMAIL_DEFAULT` и `FORM_WORK_PHONE_DEFAULT` (загружаемых из файла `.env` при его наличии). Если переменная не задана, система ДОЛЖНА (MUST) использовать встроенные демо-значения по умолчанию (`@roga-i-kopyta.com` и `+7(800)000-00-00`). Предзаполненные значения ДОЛЖНЫ (MUST) отображаться и после отправки формы (POST `/generate`).

#### Scenario: Открытие главной страницы

- **WHEN** пользователь открывает главную страницу приложения
- **THEN** отображается форма с шестью полями и подсказкой, какие поля обязательны, а в области предпросмотра — заглушка «Здесь появится ваш QR-код»

#### Scenario: Отправка формы без обязательного поля

- **WHEN** пользователь пытается отправить форму, не заполнив обязательное поле
- **THEN** браузер блокирует отправку и указывает на незаполненное поле (встроенная HTML5-валидация)

#### Scenario: Предзаполненные значения из .env

- **WHEN** в `.env` заданы `FORM_EMAIL_DEFAULT` и `FORM_WORK_PHONE_DEFAULT` и пользователь открывает форму
- **THEN** поля email и рабочего телефона предзаполнены значениями из `.env`

#### Scenario: Предзаполненные значения без .env

- **WHEN** файл `.env` отсутствует и пользователь открывает форму
- **THEN** поля email и рабочего телефона предзаполнены встроенными демо-значениями

### Requirement: Генерация и предпросмотр QR-кода

Система ДОЛЖНА (SHALL) принимать данные формы (POST `/generate`), генерировать изображение с QR-кодом и отображать его на той же странице в области предпросмотра вместе с обращением к пользователю по имени из поля ФИО.

#### Scenario: Успешная генерация

- **WHEN** пользователь заполнил обязательные поля и нажал «Сгенерировать QR-код»
- **THEN** на странице появляется изображение с QR-кодом (встроенный base64 PNG) и текст «Ваш QR-код, <имя>»

### Requirement: Скачивание и печать результата

Система ДОЛЖНА (SHALL) предоставлять рядом с предпросмотром кнопку «Скачать» (сохранение изображения в формате PNG) и кнопку «Печать» (отправка страницы на печать средствами браузера).

#### Scenario: Скачивание изображения

- **WHEN** пользователь нажимает «Скачать» после генерации
- **THEN** браузер сохраняет PNG-файл с изображением QR-кода

#### Scenario: Печать изображения

- **WHEN** пользователь нажимает «Печать» после генерации
- **THEN** открывается диалог печати браузера с текущей страницей

### Requirement: Серверная валидация данных формы

Система ДОЛЖНА (SHALL) проверять данные формы на сервере при POST `/generate` до начала генерации: поля ФИО, должность, email и рабочий телефон ДОЛЖНЫ (MUST) быть заполнены (непустые после удаления пробельных символов по краям), поле email ДОЛЖНО (MUST) соответствовать формату `текст@текст.текст`. Поля добавочного и мобильного телефонов НЕ ДОЛЖНЫ (MUST NOT) требоваться.

При наличии ошибок система ДОЛЖНА (SHALL): не генерировать QR-код, вернуть статус HTTP 400 и отобразить страницу с формой и человекочитаемым сообщением обо всех найденных ошибках. Запрос с невалидными данными НЕ ДОЛЖЕН (MUST NOT) приводить к ошибке HTTP 500.

#### Scenario: Отправка без обязательного поля

- **WHEN** приходит POST `/generate` без поля «ФИО» (или с пустым значением)
- **THEN** система возвращает HTTP 400 и страницу с сообщением об ошибке, QR-код не генерируется

#### Scenario: Некорректный email

- **WHEN** приходит POST `/generate` с email, не содержащим `@` или доменную часть
- **THEN** система возвращает HTTP 400 и страницу с сообщением об ошибке

#### Scenario: Валидные данные с пустыми необязательными полями

- **WHEN** приходит POST `/generate` с заполненными обязательными полями и пустыми добавочным/мобильным телефонами
- **THEN** система возвращает HTTP 200 и страницу с предпросмотром QR-кода

#### Scenario: Сообщение содержит все ошибки

- **WHEN** приходит POST `/generate` с несколькими невалидными полями (пустое ФИО и некорректный email)
- **THEN** сообщение об ошибке перечисляет все проблемные поля, а не только первое

### Requirement: Маски ввода телефонов

Система ДОЛЖНА (SHALL) автоматически форматировать номер в полях рабочего и мобильного телефона по мере ввода в вид `+7(XXX)XXX-XX-XX` (цифры извлекаются из введённого, ведущие `7`/`8` нормализуются в код страны). Поле добавочного телефона ДОЛЖНО (MUST) принимать только цифры и дефис. Маски НЕ ДОЛЖНЫ (MUST NOT) требовать внешних библиотек и работать офлайн.

#### Scenario: Автоформатирование при вводе

- **WHEN** пользователь вводит в поле рабочего телефона цифры `8001234567`
- **THEN** значение поля отображается как `+7(800)123-45-67`

#### Scenario: Ввод с ведущей восьмёркой

- **WHEN** пользователь вводит `88001234567`
- **THEN** значение поля нормализуется к `+7(800)123-45-67`

#### Scenario: Фильтр добавочного номера

- **WHEN** пользователь вводит в поле добавочного телефона буквы или спецсимволы
- **THEN** в поле остаются только цифры и дефис

### Requirement: Проверка email до отправки

Система ДОЛЖНА (SHALL) при отправке формы проверять email на соответствие формату `текст@текст.текст` на клиенте. При несоответствии система ДОЛЖНА (SHALL) заблокировать отправку и показать сообщение об ошибке на странице без её перезагрузки. При отключённом JavaScript форма ДОЛЖНА (MUST) работать как раньше (HTML5-валидация и серверная проверка).

#### Scenario: Некорректный email блокирует отправку

- **WHEN** пользователь ввёл email без `@` или доменной части и нажимает «Сгенерировать QR-код»
- **THEN** форма не отправляется, на странице появляется сообщение об ошибке, фокус переходит в поле email

#### Scenario: Корректный email отправляется

- **WHEN** пользователь ввёл корректный email и нажимает «Сгенерировать QR-код»
- **THEN** форма отправляется, страница показывает предпросмотр QR-кода

### Requirement: Настройка параметров запуска сервера

Система ДОЛЖНА (SHALL) читать параметры запуска из переменных окружения (`FLASK_DEBUG`, `FLASK_HOST`, `FLASK_PORT`, загружаемых из файла `.env` при его наличии). Если переменная не задана, используются значения по умолчанию: режим отладки включён (`FLASK_DEBUG=true`), адрес `127.0.0.1`, порт `5000`. Для размещения на сервере администратор ДОЛЖЕН иметь возможность отключить режим отладки и сменить адрес/порт без правки кода.

#### Scenario: Запуск с параметрами по умолчанию

- **WHEN** переменные `FLASK_*` не заданы и приложение запускается (`python app.py`)
- **THEN** сервер стартует на `127.0.0.1:5000` с включённым режимом отладки

#### Scenario: Параметры запуска из .env

- **WHEN** в `.env` заданы `FLASK_DEBUG=false`, `FLASK_HOST=0.0.0.0`, `FLASK_PORT=8080`
- **THEN** сервер стартует на `0.0.0.0:8080` без режима отладки (одним процессом — Ctrl+C останавливает его корректно)

### Requirement: Ссылка на шаблоны визиток

Система ДОЛЖНА (SHALL) отображать кнопку «Перейти в папку "Шаблоны визиток"» рядом с результатом генерации только если задана непустая переменная окружения `CARD_TEMPLATE_URL` (загружаемая из файла `.env` при его наличии). Адрес ссылки ДОЛЖЕН (MUST) равняться значению переменной. Если переменная не задана или пуста, кнопка НЕ ДОЛЖНА (MUST NOT) отображаться на странице. Адрес НЕ ДОЛЖЕН (MUST NOT) быть захардкожен в шаблоне.

#### Scenario: Переменная задана — кнопка видна

- **WHEN** в `.env` задана `CARD_TEMPLATE_URL=https://example.com/templates` и пользователь сгенерировал QR-код
- **THEN** рядом с результатом отображается кнопка «Перейти в папку "Шаблоны визиток"» со ссылкой `https://example.com/templates`

#### Scenario: Переменная не задана — кнопки нет

- **WHEN** переменная `CARD_TEMPLATE_URL` не задана и пользователь сгенерировал QR-код
- **THEN** кнопка «Шаблоны визиток» на странице отсутствует
